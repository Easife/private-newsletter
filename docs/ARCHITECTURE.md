# 架构说明

## 边界

新版本只有一个业务运行环境：Windows Python。OpenCode 由总调度器按需调用无界面的 `opencode run`，不承担抓取、缓存或编排职责，也不需要常驻 HTTP 服务。PowerShell 只负责计划任务入口，Python 是唯一总调度器。

根目录的 `运行每日新闻.cmd` 会启动只监听 `127.0.0.1` 的本机控制中心。网页只负责读取状态、编辑配置和触发 Python 总调度器；它不会在浏览器中执行抓取、评分或翻译逻辑。

## 状态流

| 阶段 | 输入 | 输出 | 关键保证 |
|---|---|---|---|
| fetch | 来源配置 | `01_raw.json` | 并发结果确定性排序、稳定 `item_id` |
| filter | 原始新闻、启动时刻 | `02_filtered.json` | 过去 24 小时滚动窗口；空结果立即失败 |
| deduplicate | 当日新闻 | `03_events.json` | 稳定 `event_id`；leader 不重复进入成员列表 |
| rank | 事件、真实兴趣 | `04_ranking.json` + `candidate_audit.json` | 规则构造 60 条候选；AI 一次返回 Top15+25；本地校正 Top15 |
| translate | 最终 40 个事件 | `05_translation.json` | GTX 成功即采用；标题失败才触发一次 OpenCode 补救与 Top10 语义检查 |
| render | 排名、译文 | 三种简报格式 | 转义 HTML、过滤非 HTTP(S) URL、只用 leader 图片 |
| publish | 完整渲染结果 | archive + latest | 分配 `newsletter-YYYYMMDD-N` 当日序号，拒绝覆盖，最后写 `current.json` 指针 |

## 完整运行与同日增量运行

每天按所选业务时区第一次成功生成时执行完整流程。同一天再次生成时，系统寻找代码指纹、版本和持久配置哈希完全一致的最近成功运行作为基线。新一轮仍会抓取并进行规则过滤与事件合并，但只有基线原始数据中不存在的全新事件进入 AI 评分和翻译；随后它们与旧结果合并，再恢复为既定的头条与普通新闻数量。

来源、权重、公式、数量、长期兴趣或代码发生变化时，基线不再兼容，下一次自动回到完整运行。一次性兴趣不参与持久配置哈希，以便它在同日增量模式下只影响新事件。

## 失败与恢复

`manifest.json` 记录版本、Python 源码指纹、日期、配置哈希和每个阶段状态。`--resume` 只允许恢复相同源码、同一日期、同一配置哈希的运行；已完成阶段还必须存在对应产物。修改代码或配置后必须新建运行，因此旧排名不会错套到新事件。

管线不再有“指定日期无结果时退回所有新闻”的行为。任何阶段失败都会标记清单，且不会更新最新版指针。

## OpenCode 调用

客户端调用本机 `opencode run --pure --format json`。每个请求通过临时附件文件传入系统要求、新闻数据和 JSON Schema，从而规避 Windows 命令行长度限制；程序解析 JSON 事件流、提取模型文本、执行稳定 ID 和字段校验，最后删除临时文件与 OpenCode session。

所有新闻正文都明确视为不可信数据，模型被要求不调用工具且只返回 JSON。CLI 未开启 `--auto` 权限；即使模型输出格式不正确，业务层仍会拒绝未知、重复或遗漏的 ID。

## 经济模式选择协议

候选池规则只用于减少漏报，不代表最终重要性：优先保留多来源事件，为每个活跃来源保留最多三条基本审阅机会，限制单一来源通常不超过八条，并加入少量兴趣候选和五条来源平衡通配候选。RSS 或 Google News 的原始出现位置不参与候选或排序。

每个候选发给 AI 的字段严格限制为 `event_id`、标题、最多 300 字摘要。媒体名称、权重、来源数量、时间戳、来源配置标签及规则分数不会发送给 AI。兴趣清单只在整次请求中出现一次，作为公共重要性之后的次要参考。

AI 返回严格排序且带分数的 Top15，以及从其余候选选出的 25 条无序新闻。Top15 随后应用本地公式：媒体权重被映射到 0.90–1.00 系数，多来源独立报道加 0/2/4/6 分。校正后前 10 条为头条，第 11–15 条位于普通新闻前五条，其余 25 条使用数据集确定性种子随机排列。

## 兴趣生命周期

- 长期兴趣保存在 `interests.yaml` 的 `long_term` 中，每次 AI 选择都作为次要参考；改变它会使现有增量基线失效。
- 一次性兴趣保存在 `recent` 中，只参与下一次生成。生成成功后总调度器原子清空该列表；生成失败时保留，避免用户意图丢失。

兴趣不产生独立分数，也不参与来源权重或多来源加分。

## 本机控制中心

控制中心提供以下本地接口：`/api/status` 返回环境、模式、进度和日志；`/api/history` 返回最近 20 份归档；`/api/settings` 读取和校验配置；`/api/generate` 启动一次生成。服务拒绝非同源写请求，并只允许绑定 localhost。设置保存前会备份原配置，管线运行期间禁止写设置。

`candidate_audit.json` 保存每个事件进入或落选 60 条候选池的原因、AI 原始选择、本地分数调整以及未入选的储备事件，便于审计遗漏和来源偏差。

OpenCode Zen 的免费模型会拒绝 `opencode serve` 的外部 HTTP 自动化请求，但允许 `opencode run`。因此当前生产配置使用 CLI 模式；HTTP 客户端代码仅作为未来付费/API 模型兼容路径保留。
